# GitHub raw — открывать во вкладке

Расширение для Vivaldi (подходит любой браузер на Chromium: Chrome, Edge, Brave). Видео, аудио, PDF, картинки и текстовые файлы из репозиториев GitHub с ним открываются прямо во вкладке, а не скачиваются.

## Зачем

Ссылки вида `https://github.com/<org>/<repo>/blob/<ветка>/<путь>/файл.mp4?raw=true` и кнопка «Raw» перенаправляют на `raw.githubusercontent.com` (для Git LFS, хранилища больших файлов, — на `media.githubusercontent.com`). Оттуда GitHub специально отдаёт двоичные файлы с заголовком `Content-Type: application/octet-stream` и политикой `Content-Security-Policy: … sandbox`, чтобы репозитории не использовали как файловый хостинг. Браузер видит «неизвестные байты» и показывает диалог «Загрузить файл?».

## Как работает

Расширение использует встроенный в Chromium механизм `declarativeNetRequest`: браузер сам применяет правила из `rules.json` к заголовкам ответа. Код расширения при этом не выполняется, страницы оно не читает. Для URL на `raw.githubusercontent.com` и `media.githubusercontent.com`, которые кончаются на известное расширение файла (допустим хвост `?token=…`), правило:

- ставит правильный `Content-Type` (например, `video/mp4`);
- удаляет `Content-Disposition` (на случай, если GitHub потребует скачивание);
- удаляет `Content-Security-Policy`: с директивой `sandbox` встроенный просмотрщик PDF блокируется.

Правила срабатывают только для документа во вкладке или во фрейме (`main_frame`, `sub_frame`). Загрузки, которые сайты делают для своих нужд, не затрагиваются. Права расширения ограничены этими двумя доменами, остальные сайты оно не видит.

| Тип | Расширения файлов | Content-Type |
|---|---|---|
| Видео | `mp4`, `m4v` | `video/mp4` |
| | `webm` | `video/webm` |
| | `ogv` | `video/ogg` |
| Аудио | `mp3` | `audio/mpeg` |
| | `m4a` | `audio/mp4` |
| | `ogg` | `audio/ogg` |
| | `wav` | `audio/wav` |
| Документы | `pdf` | `application/pdf` |
| Картинки | `png` | `image/png` |
| | `jpg`, `jpeg` | `image/jpeg` |
| | `gif` | `image/gif` |
| | `webp` | `image/webp` |
| | `bmp` | `image/bmp` |
| Текст | `txt`, `log` | `text/plain; charset=utf-8` |

Регистр расширения не важен (`.MP4` тоже сработает). `svg` и `html` намеренно не включены: в них может быть JavaScript, и без CSP он выполнился бы на домене GitHub.

## Скачивание

Любой из двух способов:

- **Через git** (так проще обновляться):
  ```
  git clone https://github.com/e-dorado/public.git
  ```
- **Архивом:** на странице https://github.com/e-dorado/public нажать **Code → Download ZIP** и распаковать.

Нужна папка `github-raw-inline` внутри скачанного. Положите её туда, где она будет лежать постоянно, см. «Важно знать».

## Установка

1. Открыть в Vivaldi адрес `vivaldi://extensions` (в Chrome — `chrome://extensions`, в Edge — `edge://extensions`).
2. Включить **«Режим разработчика»** переключателем (в Vivaldi и Chrome — справа вверху).
3. Нажать **«Загрузить распакованное»** и выбрать папку `github-raw-inline` (ту, где лежит `manifest.json`).
4. Появится карточка «GitHub raw — открывать во вкладке». Проверьте, что она включена и под ней нет красной кнопки «Ошибки».

Проверка: открыть ссылку «Raw» любого `.pdf` или `.mp4` в репозитории на GitHub. Файл должен открыться во вкладке. Скачать файл всё равно можно: в плеере через «⋮ → Скачать», в PDF кнопкой загрузки на панели.

## Важно знать

- Расширение загружено **из папки**: удалите или переименуйте её, и оно перестанет работать. Лучше держать папку на месте.
- Распакованное расширение живёт только в этом профиле на этой машине. Синхронизация Vivaldi его **не переносит**, на другом компьютере повторите установку.
- Chromium может при запуске показывать предупреждение о расширениях в режиме разработчика. Это нормально, можно закрыть.

## Обновление расширения

1. Скачали через git: в папке репозитория выполнить `git pull`. Скачали архивом: скачать ZIP заново и заменить файлы в той же папке.
2. На `vivaldi://extensions` нажать **⟳** (перезагрузить) на карточке расширения.

## Свои правила

1. Отредактировать `rules.json`. У каждого правила должен быть уникальный `id`, а в `regexFilter` расширение файла подставляется так же, как в существующих правилах.
2. На `vivaldi://extensions` нажать **⟳** (перезагрузить) на карточке расширения.
3. Если в JSON (формате файла правил) ошибка, на карточке появится «Ошибки» с описанием.

Ограничить правила репозиториями одной организации: в каждом `regexFilter` заменить `githubusercontent\.com/.*` на `githubusercontent\.com/<организация>/.*`.

Свои правки при `git pull` могут конфликтовать с обновлениями из репозитория. Если правите правила, лучше держать копию папки отдельно.

## Ограничения

- `.mov` и видео в кодеке HEVC (H.265) Chromium не воспроизводит даже с правильным заголовком: будет ошибка или чёрный экран. Такие файлы открывайте во внешнем плеере (кнопка «Открыть» в диалоге загрузки).
- Ролики, загруженные перетаскиванием в issue или комментарий (`github.com/user-attachments/…`), GitHub и так показывает плеером, расширение для них не нужно.

## Если не работает

| Симптом | Что проверить |
|---|---|
| По-прежнему диалог «Загрузить файл?» | Расширение включено? Расширение файла есть в таблице выше? Узел в диалоге — `raw.githubusercontent.com` или `media.githubusercontent.com`? |
| Чёрный экран или «формат не поддерживается» | Скорее всего, `.mov` или HEVC, см. «Ограничения». |
| PDF: «Страница заблокирована» | После правки `rules.json` не нажали ⟳, либо из правила пропало удаление `content-security-policy`. |
| Вкладка открылась, но пустая или 404 | Истёк `?token=…` в URL приватного репозитория. Откройте ссылку заново со страницы GitHub. |

## Удаление

`vivaldi://extensions` → «Удалить» на карточке расширения. После этого папку можно удалить.
